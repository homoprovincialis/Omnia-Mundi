1. ОБЩИЙ ВИД

- Современный, простой, утилитарный универсальный международный маркетплейс.
- Полностью белый фон (#FFFFFF), основной текст чёрный (#000000), вспомогательные
  подписи спокойного серого цвета (#6B7280), тонкие разделители #E5E7EB.
- Единственный умеренный цвет интерфейсной ссылки — синий около #2463CC.
  Цвета интерфейса НЕ являются частью логотипа.
- Без рекламных баннеров, слоганов, hero-блоков, больших иллюстраций,
  глобусов, градиентов, подложек из цветных карточек, рекламных каруселей,
  пафосных цитат, гигантских заголовков и декоративных «историй».
- Вся страница посвящена выбору товара; главная область сразу показывает каталог.
- Относительно небольшие шрифты интерфейса; хорошая читаемость; умеренная
  плотность, без тяжёлых рамок. Не оформлять как старый сайт 2000-х годов.
- Полезная ширина: большой адаптивный контейнер с небольшими боковыми полями;
  НЕ делай гигантские изображения для заполнения широкого монитора.

3. ГЛАВНАЯ СТРАНИЦА: СОСТАВ СВЕРХУ ВНИЗ

3.1. Верхняя строка (компактная шапка):

  [OMNIA-MUNDI]  [значок лупы  Поиск товаров…___________________]  [Войти] [Корзина]

  - Логотип слева, основная строка поиска по центру, справа компактные
    пиктограммы человека и корзины с понятными текстовыми метками
    («Войти», «Корзина») или доступными подписями на малом экране.
  - Поле ввода имеет видимое описание «Поиск товаров…».
  - Не вводить огромную рекламную шапку.
  - Под шапкой тонкая светло-серая горизонтальная линия.

3.2. Одна горизонтальная строка основного меню; точные надписи и порядок:

    Каталог  |  Производители  |  Бесплатные товары  |  Запросы

    справа, с небольшим знаком «+»:  Найти отсутствующий товар

  - «Каталог» ведёт к разделу каталога на ЭТОЙ странице.
  - Все остальные названия — зарезервированная навигация будущих модулей.
    Пока они НЕ должны выдавать ошибку 404 и НЕ должны притворяться
    функционирующей торговой операцией. Допустима простая нейтральная
    индикация «Раздел находится в разработке» при активации.
  - В частности, «Найти отсутствующий товар» в будущем ведёт к созданию
    Product Request, но на этапе 1 форму запроса не программировать.
  - После меню тонкая светло-серая горизонтальная линия.

3.3. Основная область: узкая левая колонка фильтров (~116 px) и каталог справа.
     Межколоночный промежуток ориентировочно 12–16 CSS px.

  ЛЕВАЯ КОЛОНКА: точные заголовки и надписи в макете:

    Категории
      Все товары
      Электроника

      Инструменты

  - Это компактные простые текстовые элементы на белом фоне.
  - Категории как фильтр работают только в пределах показанного ДЕМО-каталога;
    если фильтрация реализована, она должна быть корректной и не требовать API.
  - Для страны и цены на этапе 1 достаточно корректной визуальной секции;
    НЕ имитировать ложные поисковые результаты.

  ПРАВАЯ КОЛОНКА:

    Каталог товаров                                       [Фильтры]
    [фото] [фото] [фото] [фото]
    Назв.  Назв.  Назв.  Назв.
    €...   €...   €...   €...
    Страна Страна Страна Страна

    [фото] [фото] [фото] [фото]
    ... ещё одна строка ...

  - Компактный заголовок «Каталог товаров»; справа небольшой значок
    ползунков и подпись «Фильтры».
  - Сетка ровно 4 КОЛОНКИ на настольных экранах (широкие браузеры).
  - РАЗМЕР КАЖДОЙ ФОТОГРАФИИ — РОВНО 118 × 118 CSS px на десктопе,
    форма строго квадратная, object-fit: cover/contain по смыслу фото,
    НЕ растягивать с ростом ширины окна.
  - Горизонтальные промежутки около 8–12 px; картинки и подписи
    выровнены по левому краю, без больших рамок карточек.
  - Под каждой фотографией: название товара небольшим чёрным шрифтом,
    под ним цена в евро, ниже ещё меньшим серым шрифтом страна.
  - Показать минимум 8 разных демонстрационных товаров в ДВЕ строки.
    Ранее в макете были: наушники, чашка, кошелёк, лампа;
    сумка, термос, шуруповёрт, часы. Это ПРИМЕРЫ КАРТИНОК,
    не реальные предложения и не утверждённые цены.
  - Фото должны изображать реальные предметы, а не абстрактные фигуры
    и не символы Unicode. Для локальных фото проверить разрешение
    на использование; записать источник и лицензию в ASSETS.md.
    Не подгружать случайные коммерческие изображения без разрешения.
    Если подходящих фотографий нет и нельзя получить разрешённые,
    СПРОСИТЬ владельца, не подменять их непохожими рисунками.
  - Около каталога нужна незаметная надпись «Демонстрационные товары»,
    чтобы исключить впечатление, будто покупки уже реально доступны.
  - Цена в EUR, десятичный разделитель запятая, символ €.

фальшивых торговых действий. Не создавать новый большой верхний блок,
«карточки проектов» или плашки под эти направления.

6. МОБИЛЬНАЯ ВЕРСИЯ

- На телефоне (например ширина 390 CSS px) товары строго в ДВА столбца;
  квадратные изображения не крупнее 118 × 118 px, без растягивания.
- Шапка остаётся компактной, поиск удобен для использования.
- Левая панель фильтров прячется в раскрывающуюся область, доступную через
  кнопку «Фильтры». Вся страница не должна прокручиваться горизонтально.
- Навигация доступна без обрезки: корректный перенос или компактное меню,
  не добавляя и не переименовывая разделы.
- Текст, кнопки и элементы должны быть нажимаемыми и доступны с клавиатуры.

7. ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ ДЛЯ ПРОСТОГО ПЕРВОГО ШАГА

- Создать полностью НОВЫЙ визуальный фронтенд в отдельной ветке от чистой main.
- Без зависимости от старого прототипа, без backend/API/SQLite/платёжной библиотеки.
- Для первой статической страницы достаточно index.html, style.css,
  app.js при необходимости, assets/ и README. Можно использовать простые
  веб-стандарты HTML/CSS/JS. Не усложнять архитектуру без причины.
- Держать лого как отдельный точный SVG-файл, показывать через <img>,
  не воссоздавать надпись другим шрифтом средствами CSS.
- CSS-параметры фотографий фиксировать в явных правилах, например
  width:118px; height:118px; aspect-ratio:1 / 1. Сетку формировать явно
  для 4 столбцов на десктопе.
- Семантический HTML, alt для фото, aria-label для иконок/поля поиска,
  видимая фокусировка и достаточная контрастность.
- Статическая страница должна открываться локально, без внешних секретов.
  Изображения и логотип хранить внутри репозитория, чтобы всё открывалось
  без посторонних серверов.
- Текст интерфейса на ЭТОМ этапе — русский, как в утверждённом макете.
  Архитектуру строк сделать пригодной для будущих переводов, но не создавать
  многоязычный интерфейс без дополнительного решения владельца.
- Не скрывать недоделки фиктивными данными о продавцах, рейтингах, наличии,
  сроках доставки, скидках и объёмах продаж.
